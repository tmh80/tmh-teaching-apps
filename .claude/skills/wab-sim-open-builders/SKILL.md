# WAB Sim Open Builders

Companion to `wab-science-sim-builder`, which holds the design rules, shell, build, testing and delivery: load that core skill too. Section numbers match across the skills. Questions about a build follow `wab-sim-review-questions` (sections 4a-2 and 4a-3). Build sheets, the teacher page and marking also need `wab-sim-toddle-outputs` (sections 4b–4d).

## 4e. Open builders and build tasks

Open interaction matters: every sim has a **Builder's Workshop** (or the sim's equivalent) on the home screen with 2–4 open builders of the unit's key things. Examples: circuit builder (free-form PhET-style board, all parts), atom builder (protons/neutrons/electrons with element card and charge), power grid designer (randomised map), food web builder, ecosystem/island designer, simple machine builder.

- **Free build** plus **template build tasks**. Each task has: id, title, minutes, a goal sentence, a brief, 2–4 **live checks** shown as chips that turn green only when the build really passes (computed from the model, e.g. the circuit solver with what-if tests: "each switch turns off only its own bulb"), a results table (filled from what the student actually did), 1–3 Review-style questions about their own build (each with a model answer), a marking rubric `[[criterion, marks], …]`, a **model build** description and **example results** for the answer key.
- **Builders save and restore state** (`getState()` / `state` option) and expose the SVG for a snapshot.
- **Map builders are randomised from a seed** with varied conditions (coast, river, mountains, windy hills, volcano, forest, farmland; weather such as sun, wind, rain and tides; demand). Students tap squares to read conditions and drag objects onto the map (ghost tile shows green/red for allowed/not allowed, with a reason when refused), use a remove tool (refund if built this round, part-value sale if older, with undo), then run a simulation. Limits keep it honest (e.g. two dams per river, three biomass plants). Tasks can force conditions (calm and cloudy) and set budgets. Draw each square's objects so they never overlap (one object per square, connections drawn between square centres).
- **Students build the connections too** (power lines, pipes, food-web arrows) by dragging square to square, and connections have real consequences: cost per square by terrain, losses with length, capacity limits and upgrades (e.g. high-voltage lines). Unconnected items get a red "!" badge.
- **Simulate a whole year, show an average day.** Run the model across the seasons (e.g. 12 typical days weighted by month), replay the **average day** hour by hour on the map and chart, then summarise in plain words: "There were blackouts on 42 days this year. They happened between 17:00 and 21:00. Why? The sun has set, and the battery is empty. When in the year? Dec, Jan, Feb." Every failure is explained with its cause; nothing goes wrong silently.
- **Charts explain themselves:** a short legend under the chart (line = what's needed, bars = what was made, faded = stored, striped = wasted, red = shortfall) and a "How do I read this chart?" fold-out.
- **Story mode for scaffolding.** Before (or beside) free build, offer 4–5 short chapters that each teach one idea with a prediction first, a few live goals and a short debrief, unlocking in order (teacher mode unlocks all). End with a big open challenge with real trade-offs, e.g. The Big Switch: start from a realistic existing system (a coal and gas grid, already paid for and connected), play in 5-year rounds to 2050 with income, fuel, upkeep, a rising carbon tax, falling clean-tech prices and blackout costs, so switching too fast goes bankrupt and too slow is ruined by the tax. Free build and design tasks also start from the existing fossil system so students have something to work from.
- **Scorecard of positives and consequences.** After each run, show star ratings (reliability, cost, climate) and a card per item listing what's good ✅ and what it costs ⚠️ (materials, whole-life CO₂, land flooded, waste), with totals. Use verified figures with a source line (e.g. IPCC whole-life gCO₂/kWh medians) and avoid oversimplified claims; check every science claim before shipping.
- **Check every build task and story chapter is achievable** with a script before shipping: a Node harness that loads the model source and runs an exhaustive or greedy search over many seeds for the cheapest valid build. **Re-check whenever the model changes** (e.g. moving from one day to a whole year). Then set budgets/targets a little above the hardest map so the challenge is real but always possible.
- **Build sheet** (`buildSheet(builder, task, mode)`), same three modes as worksheets: student (snapshot of the build from the sim, ticked checklist, results table, question answers, all in blue, then a feedback page with the checks passed, no teacher comment box); blank template (dashed "paste a screenshot or draw it" box, empty checklist and results table with the same columns, answer lines); answer key (checklist ticked, marking rubric, model build, example results labelled "students' will differ", model answers). "Make my build sheet" lists anything unfinished with "Go to …" buttons and "Make it anyway".
- Build tasks appear on the teacher page, in step 5 and in the marking schemes like any section.

## 4f. Open research questions, evidence journal, table maker and graph maker (from Tilt Lab)

Use this when a sim has an open "investigation" part where students find their own way to an answer and hand in evidence. Tilt Lab (`tilt-lab/Tilt-Lab-offline.html`) is the reference build. The table and graph code is also kept in `shared/table-graph-maker.js`.

**Research questions.** Open questions in three levels (🌱 Foundation, 🔭 Extension, 🚀 Mastery), about four per level, none with a single route. Each has: the question; "words to use" (chips shown while writing); five or so "ideas a strong answer includes"; one possible answer; and five or six tips.
- **Tips come one at a time** (a button "Ask for a tip"). Each tip names the view or tool to open and what to look for in it, with a "Show this view" button that adds it to the dashboard. Some tips are "think" tips with no view. Tips used is counted and printed on the worksheet. Tom marks on **tips used + quality of the answer**.
- **Answer check (Force HQ style):** the words to use appear above the answer box. After submitting (at least 12 words) the answer locks and shows the key words used (auto-detected with simple word patterns), one possible answer, and a "Did you include…?" list the student ticks. Edit my answer re-opens it.
- **Pop-up instructions** (a short card stepper with Back, Next, Skip and "Do not show this again") explain the flow when the student opens the investigation. A "How it works" button reopens them. Keep one card for each of: choose, explore, tips, evidence, table and graph, answer, worksheet.
- Test the numbers in every "ideas" list and model answer against the sim itself, for the specific planets, places and dates the question names.

**The journal for the chosen question.** A side drawer (the dashboard stays visible) with a sticky status strip (tips used, evidence n of 5, answer state), tips, notes (600 characters), screenshots, tables and graphs, and the answer (900 characters). Saved per student. Picking a question from Guided mode switches to the free dashboard so the student can see the model.

**Evidence.** One shared list per question, **up to 5 pieces in total** across screenshots, tables and graphs, each with a caption of up to 160 characters ("What does this show?"). A 6th tick is blocked with a message. Deleting a table or graph needs a second press.
- **📷 Screenshot button on every view.** Copy the view's canvas onto a new canvas with a title band (view, planet, place, date and the key settings), JPEG at about 0.68 quality, 540 px wide. Draw non-canvas views (a numbers readout) onto a canvas from their text. Keep at most 12 per student, because localStorage is shared and small.

**Table maker (inside the journal drawer, not a pop-up).** The dashboard has to stay visible so students can read a number and type it in. A table has a title, up to 5 headed columns and 12 rows, 24 characters per cell. "Quick headings" chips (Date, Place, Planet, Tilt (°), Daylight (h) and so on) fill the next empty heading. Add and remove row or column buttons; removing a row or column that has writing in it asks for a second press. Students type the numbers themselves; the sim never fills cells in for them.

**Graph maker (a full-height window, ported from the Paper Plane Lab graph tool).** Keep these behaviours:
1. Choose a table, then the x column and the y column.
2. Choose **scatter graph** (numbers along the bottom) or **bar graph** (names along the bottom). Warn if scatter is chosen and the x column has words in it.
3. Write the title ("x vs y") and the axis labels with units in brackets. A "Use my column headings" button fills the labels.
4. Axis numbers: lowest, highest and gap for each axis, plus a **Suggest numbers for me** button (the x-axis starts at 0 when the data does).
5. **Drag each point onto the graph** from a tray of blue chips (scatter), or drag orange name chips into boxes under the graph and then drag the dot on top of each bar to its height (bar). Use pointer events with a ghost chip so mouse, pen and touch all work. A point or bar snaps to the true value when it lands within about 7% of the axis range. Placed points and bars can be dragged again, and a placed chip can be pressed to take it back. A wiggling hint box sits on the empty graph.
6. A **line of best fit** (two draggable round ends) or **curve of best fit** (a third middle dot bends it), and a **join the points** switch.
7. **Green and red rings** show whether each point or bar is in the right place (within about 3.5% of the axis range). A live **checklist** (type chosen, title, x label with units, y label with units, data fits the axes, all data plotted, every point right) sits under the graph.
8. Everything saves on every change. Esc or "Done: back to my journal" closes the window. The canvas is 1000 × 560 and always has a white background, so the same drawing function makes the live graph, the journal thumbnail and the worksheet picture (without rings). No chart library, no internet.
Limits: 6 tables and 6 graphs per student. On a phone the canvas moves above the controls.

**Worksheet for a research question.** Header, name/class/date, the question, a marking strip (tips used, evidence items, key words used, ideas included), notes, the evidence (screenshots two across; tables and graphs full width, each with the student's caption), the answer, and the check-my-answer lists. A teacher also gets a blank copy and an answer key.

**Worksheets never go over two A4 pages (Tom's rule for evidence sheets).** Do not rely on tidy content. Build a fit step into the worksheet viewer:
- Wrap the sheet in an inner element. Before showing it, measure the height in a hidden "print width" state (A4 minus 12 mm margins is about 703 px wide, 1032 px tall per page) and reduce a CSS `zoom` variable in small steps until it fits two pages. The same `zoom` rule applies in `@media print`.
- Pages break only between blocks. So when the sheet holds blocks that cannot split (graphs, screenshots, the marking strip), add up the space lost at each page edge while measuring and fit to about 97% of two pages. Let tables split between rows.
- Cap the content too: text boxes (notes 600, answer 900 characters), 5 pieces of evidence, a limit on rows and questions. Section worksheets use a compact layout (a chip, the prompt in grey, and the student's answer in blue, in two columns), because the full layout runs to five pages.
- In print, hide everything except the worksheet viewer (`body[data-ws] > *:not(.wsv){display:none}`), so a pop-up library or home page underneath never prints.
- Test the worst case with Playwright: maximum text, 5 pieces of evidence including two graphs and three full tables, then `page.pdf` and `pdfinfo` to count pages. The Tilt Lab worst case fits at about 78% zoom.
