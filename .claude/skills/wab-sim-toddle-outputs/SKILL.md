# WAB Sim Toddle Outputs

Companion to `wab-science-sim-builder`, which holds the design rules, shell, build, testing and delivery: load that core skill too. Section numbers match across the skills. Points, `LEVEL_CUTS` and the MYP strand table are in `wab-sim-review-questions` (section 4a-2), so load it when working on marks or levels. Build sheets and the two-page rule for evidence sheets are in `wab-sim-open-builders` (sections 4e and 4f), so load it when working on those.

## 4b. Worksheets (printable, PDF, Toddle-ready)

Every section has a worksheet built from its Review questions, in three modes from one function (`buildWorksheet(section, mode)`):
- **Student** — the student's own answers and drawings, name and date, stamps earned; auto-marked results go on a separate **Feedback page** so the work itself stays clean. **No teacher comment box on any PDF:** Tom leaves comments directly on Toddle. It opens with **"Steps completed in the sim"**: a two-column tick list of the section's Learn steps and Challenge missions, with blue ticks for those the sim recorded as done (empty boxes on the blank template; a note on the key that they are not marked). Before making it, list unanswered questions with "Go to …" buttons and "Make it anyway". **Everything the student added prints in blue** (answers, ticks, table cells, typed text, ordered lists, outlined drawings), with a line under the name bar: "Everything printed in blue was added by the student in the sim." This lets Toddle AI tell the student's work from the template.
- **Blank (the template)** — printable, for paper copies and Tom's records: answer lines, working boxes, empty tables with a choices list, order boxes (A, B, C … with the correct order to write in), large dashed drawing boxes, ruled lines for explanations. It must have exactly the same questions, order and layout as the student version.
- **Answer key** — the same sheet with every answer filled in and a model answer for every question: model drawings, model written answers, worked calculations and "Look for" checklists. Teacher-only (behind the teacher code), never reachable from student screens; its text also feeds the written answer key in the AI feedback text (section 4d).

Design: A4, always light theme, a coloured header with the sim brand, section title and topic, Name/Class/Date bar, Part A (auto-markable) then Part B (draw and explain). About 3–4 pages per section (but sheets where students hand in their own evidence stay within two pages: see section 4f); questions never split across pages (`break-inside: avoid`), headings never orphaned (`break-after: avoid`), print background white.

In the sim: a "Make my worksheet" button opens a full-screen preview with "Print or save as PDF" (`window.print()` with print CSS that hides everything but the worksheet; tell students to choose "Save as PDF" and upload to Toddle). The artifact preview blocks printing; the Toddle/browser file works. Also offer a "Blank copy" button.

- **File name.** Every PDF is named `<Section title> - <Foundation|Challenge|Extension> worksheet - <Student name>`, from one helper that strips characters file systems reject. Teacher copies end `- Blank template`, `- Answer key` or `- Marking scheme`; build sheets are `<Task title> - Build sheet - <Student name>`. Before `window.print()`, set `document.title` to the name (browsers use it as the suggested PDF name) and restore it on `afterprint`, with a timeout fallback. A direct download uses the same name.
- **Direct download (on trial in Sparks Through Time).** Some students get lost in the print menu. Sparks is trialling a "⬇ Download my worksheet (PDF)" button: html2canvas and jsPDF inlined (no CDN), the sheet paginated by the same rules as the print CSS, an invisible text layer so Toddle AI can read the text, the claude.ai downloads capability when present (as in Adapt Lab's `savePdfFromCanvases`), and the print menu kept as a backup. Until Tom confirms it works for students in Toddle on laptops and iPads, keep the print menu as the main route in other sims.

For Tom: generate static PDFs with a Playwright script (`make-worksheets.js`) that loads the built file and renders, for each section and each build task (section 4e), the blank template, the answer key and the marking scheme page, calling `page.pdf({format:'A4', printBackground:true})`. Package a **Toddle files zip** with **one folder per sheet** containing `1-Blank-Template.pdf`, `2-Answer-Key.pdf` and `3-Marking-Scheme.pdf`, plus a "READ ME" (these are for records and paper copies; Toddle's AI uses the written text from the teacher page) and the AI feedback text as one .txt. Also merge all answer keys into one PDF (`pdfunite`). Delete stale files from renamed tasks before packing.

## 4c. Teacher page: set classwork or homework

Every sim has a **"For teachers: set classwork or homework"** page, reached from a button **at the top of the home screen** (above the hero, right-aligned), that writes a prompt for Tom to paste into the **Toddle AI task maker**.

- **1. Choose:** tick boxes for the sections/stops (any number; "Select all" and "Clear") and the open-builder **build tasks** (section 4e). Keep these rows clean (no buttons on them).
- **2. What they do:** Learn steps, Challenge missions, Review questions + worksheet, Explore free play, plus extras such as a final mixed review/test and a progress screenshot (stamps/passport).
- **3. Details:** class, where it happens (In class / At home / Both, which changes the wording: splitting across evenings or lessons, a note about switching devices) and an optional message to students. **No due date field**: Tom sets dates in Toddle after the task is made. Choices save in localStorage.
- **4. Copy into Toddle:** the live prompt in a read-only box with a "Copy instructions" button (clipboard inside the click handler, falling back to selecting the text with a "Press Ctrl+C" prompt), and an estimated total time (e.g. Learn ≈ 2.5 min per step, Challenge ≈ 15, Review ≈ 20, Explore ≈ 10, each build task its own estimate). Under it: "Paste this prompt into Toddle's AI task maker. Then paste the step 5 text into the task's AI feedback settings."
- **5. AI feedback instructions** (section 4d): a read-only box with the full written AI feedback text, a "Copy" button and a live character count, under the heading "Paste this into Toddle's AI feedback box". It is behind the teacher code. If the text is very long, a note suggests setting fewer sections in one task.
- **6. Printable PDFs (optional):** one row per selected sheet (title, type, total marks) with blank template, answer key and marking scheme buttons, for Tom's own records. Say clearly that nothing needs attaching to Toddle. If stops are ticked without "Review questions + worksheet", say they have no worksheet.
- **The generated prompt**, in this order: what to create (class, sim name, "an HTML file I will attach"); task title; estimated time; a short description of the resource (including "use the same device and browser so progress saves"); numbered student instructions per selected section, part and build task, in friendly student language with the exact button names ("Make my worksheet", "Make my build sheet", "Save as PDF"); what students submit (one worksheet PDF per section, one build sheet PDF per build task, screenshot, test score); learning goals per section and build task as plain verbs (no "I can", no standards codes); key vocabulary; teacher-only notes; an **MYP objectives** line asking Toddle to attach the criteria and strands the selected sheets use (only those); and a line saying the AI feedback instructions, including a written answer key, will be pasted into Toddle's AI feedback settings separately and students must never see them. **Never put answers in this prompt:** the task maker may copy its text into the student-facing description.
- Give each section and each build task a short goal sentence, and each section a vocabulary list, in the content module. Keep task steps and briefs in the same data the sim uses, so the teacher prompt never goes out of date when a task changes.
- Test: tick several sections, parts and build tasks; check the prompt reads well and the time adds up; check copy works; open every file button; check the page at phone width.

## 4d. Toddle AI marking: templates, answer keys and marking schemes

**Toddle's AI feedback instructions can't take attachments**, so everything the AI needs is written text, built from the same question data as the worksheets (`aiFeedbackText(sheets, tasks)`), in this order:
1. **How to mark:** student answers are printed in blue and only those are marked; the template's own text, choices and word banks are not student work; the feedback page at the end of each PDF shows the sim's auto-marking (if it disagrees with the visible answer, trust the visible answer and say so); "Steps completed in the sim" ticks are not marked, but mention skipped steps; one go per auto-marked question; blank questions score 0 with a kind note; accept any correct scientific wording; no marks off for spelling unless meaning is unclear.
2. **Feedback style** for the grade: score per sheet with a per-question breakdown, one or two strengths quoting the student, one next step with a hint rather than the answer.
3. **MYP levels:** the strands the task uses with their wording, the counting rule and the level table from `LEVEL_CUTS` (section 4a-2).
4. **Written answer key**, one block per sheet: a header with the sheet title, total marks and strands, then one short line per question with its type, marks, strands and the answer (accepted words for gaps, tolerance for calculations, partial-mark rules), and for draw and explain questions a "Look for:" list plus the model answer. Build tasks list their rubric rows and questions the same way.
5. **Totals:** marks for the task and marks available for each criterion.

The printable files (blank template, answer key, marking scheme) are still made for Tom's records and paper copies:

- **Marking scheme generator** built from the same question data (`markItem`, `schemeForSection`, `schemeForTask`, `markingInstructions`). Marks per type: choose one 1; tick all 2 (1 if one missing or extra); match/table/sort 1 per cell; order 2 (1 if one neighbouring swap); calculate 2 (answer with tolerance range + working/method); fill the gaps 1 per gap with accepted spellings; choose the words 1 per drop-down; answer and reason 2 (answer 1, reason 1); spot the mistake 2 (line 1, correction 1); freeze-frame table 1 per cell, marked for consistency with the student's own snapshot (the key's values are examples); tap the moment 1 per target; sketch the graph 1 per feature check; How sure are you? not marked; draw/explain 1 per checklist point, plus the model answer and "accept any correct scientific wording". Picture-only rows are named "Row N (picture)" in the order the template shows them. Build tasks use their own rubric (section 4e).
- **Each marking scheme page opens with the same marking instructions as the AI feedback text**, so it stands on its own: **mark only what the student added** (printed in blue); the template's own text, choices and word banks are not student work; the answer key is the standard (students needn't match it word for word); use the sim's feedback page to confirm, and if it disagrees with the visible answer, trust the visible answer and say so; students are expected to complete the steps listed under "Steps completed in the sim" before answering, and a blue tick means the sim recorded that step as done (not marked, but mention skipped steps in the feedback); blank questions or an empty template score 0 with a kind note of what is missing; feedback for Grade 6–8: score per sheet with a per-question breakdown, one or two specific strengths quoting the student, one next step with a hint rather than the answer; no marks off for spelling unless meaning is unclear. End with the total marks.
- **Teacher code:** answer keys, marking schemes and the AI feedback text on the teacher page, and the "I'm a teacher" mode, are **locked behind a code that is the first word of the sim's name in capitals** (Sparks Through Time → SPARKS; Force HQ → FORCE; Adapt Lab → ADAPT), case-insensitive. Remember the unlock in localStorage with a "Lock again" button. Locked buttons show 🔒 and scroll to the code box. Blank templates are never locked.
